# Trading Web UI 가이드

## 목적

이 문서는 Trading Web 전체 화면의 시각 언어와 UI 구현 원칙을 정리합니다. 디자이너, 퍼블리셔, 프론트엔드 개발자가 새 화면이나 컴포넌트를 만들 때 공통 기준으로 사용합니다.

## 제품 UI 개요

현재 제품은 다크 테마 기반의 반응형 가상자산 거래 화면입니다. 한 화면 안에 다음 영역을 배치합니다.

- 상단: 브랜드, 주요 메뉴, 언어, 입금 및 계정 액션
- 시장 정보: 종목 선택과 가격 통계
- 중앙: 가격, 호가 깊이, 펀딩, 종목 상세 차트
- 우측: 오더북과 주문 입력
- 하단: 포지션, 미체결 주문, 체결, 주문 내역, 펀딩 내역
- 최하단: 네트워크 상태와 지원 메뉴

데스크톱에서는 여러 패널을 동시에 보여 주고, 모바일에서는 차트·오더북·주문을 탭으로 전환합니다.

## 디자인 방향

- 많은 거래 정보를 빠르게 비교할 수 있도록 장식보다 밀도와 계층을 우선합니다.
- 패널 경계, 약한 배경 차이, 텍스트 명도로 정보 그룹을 구분합니다.
- 상승·매수는 녹색 계열, 하락·매도는 빨간색 계열을 일관되게 사용합니다.
- 주요 행동은 보라색 브랜드 컬러로 강조합니다.
- 수치와 레이블은 크기, 굵기, 명도 차이로 우선순위를 만듭니다.
- 애니메이션은 상태 변화를 이해시키는 짧은 피드백에만 사용합니다.

## 디자인 토큰

토큰의 기준 파일은 다음과 같습니다.

- 크기, 간격, 레이어, 모션: `src/styles/_tokens.scss`
- 색상: `src/styles/_color-token.scss`
- 공통 레이아웃 믹스인: `src/styles/_mixins.scss`

새 스타일에 임의의 색상, 간격, 폰트 크기, z-index를 추가하기 전에 기존 토큰을 우선 사용합니다. 반복되는 값이 필요하면 토큰에 의미 있는 이름으로 추가합니다.

### 핵심 색상

| 용도 | 토큰 | 현재 값 |
| --- | --- | --- |
| 브랜드·주요 선택 | `$color-primary` | `#7774ff` |
| 전체 배경 | `$color-bg` | `#212124` |
| 기본 표면 | `$color-surface` | `#212124` |
| 떠 있는 표면 | `$color-surface-raised` | `#303033` |
| 경계선 | `$color-border` | `#494950` |
| 기본 텍스트 | `$color-text` | `#ffffff` |
| 보조 텍스트 | `$color-text-muted` | `#888891` |
| 상승·긍정 | `$color-positive` | `#00d6a3` |
| 하락·부정 | `$color-negative` | `#ff535b` |
| 오더북 매수 | `$color-book-bid` | `#1affb9` |
| 오더북 매도 | `$color-book-ask` | `#ff5c5c` |

상승과 하락을 색상만으로 전달하지 않습니다. `+/-` 부호, 방향 텍스트, 아이콘 등 두 번째 단서를 함께 제공합니다.

### 타이포그래피

- 기본 글꼴: `Satoshi`
- 대체 글꼴: 시스템 UI 글꼴
- 루트 크기: `62.5%`로 설정되어 `1rem = 10px`에 가깝게 사용
- 본문 기본 크기: `1.4rem`
- 지원 범위: `1rem`부터 `4rem`
- 기본 굵기: `400`
- 강조 굵기: `500`

새로운 글자 크기를 직접 선언하기보다 `$font-xs`부터 `$font-4xl`까지의 토큰을 사용합니다. 숫자 열은 자릿수 변화로 레이아웃이 흔들리지 않는지 확인합니다.

### 간격과 모서리

- 간격 토큰은 `0`부터 `5.4rem`까지 정의되어 있습니다.
- 주요 간격은 `0.4`, `0.8`, `1.2`, `1.6`, `2.4`, `3.2rem` 계열을 사용합니다.
- 모서리 반경은 `0.3`, `0.4`, `0.8`, `1.2rem` 네 단계입니다.
- 거래 패널의 경계는 얇고 평평하게, 메뉴·툴팁·버튼은 필요할 때만 반경을 적용합니다.

### 레이어

| 토큰 | 값 | 용도 |
| --- | ---: | --- |
| `$z-chart` | 1 | 차트 내부 |
| `$z-market` | 10 | 시장 선택 |
| `$z-popover` | 20 | 팝오버 |
| `$z-menu` | 30 | 메뉴 |
| `$z-tip` | 50 | 안내 레이어 |
| `$z-tooltip` | 60 | 툴팁 |

새 z-index를 임의로 크게 지정하지 말고 레이어 체계 안에서 해결합니다.

### 모션

- 빠른 피드백: `0.15s`
- 일반 전환: `0.2s`
- 큰 전환: `0.4s`
- 스켈레톤: `1.2s`

`prefers-reduced-motion: reduce` 대응이 공통 스타일에 있으므로 새로운 애니메이션도 이 설정에서 제거되거나 축소되어야 합니다.

## 레이아웃

### 데스크톱

상단·하단 바를 제외한 거래 영역은 CSS Grid입니다.

```text
┌──────────────── 시장 정보 ───────────────┬── 오더북 ──┬── 주문 ──┐
├──────────────── 차트 ────────────────────┼── 오더북 ──┤         │
├──────────────── 포지션/내역 ─────────────┴─────────────┤         │
└────────────────────────────────────────────────────────┴─────────┘
```

- 기본 오더북 너비: `30rem`
- 기본 주문 영역 너비: `32.4rem`
- 차트 영역: 남은 너비를 사용하며 최소 `52rem`
- 패널 사이의 1px 간격과 경계 색상으로 구획을 나눕니다.
- 포지션 패널을 접으면 차트 영역이 남은 높이를 확장해 사용합니다.

### 반응형 기준

| 구간 | 기준 | 동작 |
| --- | --- | --- |
| Desktop 축소 | `80rem` 이하 | 오더북과 주문 영역 너비 축소 |
| Tablet | `64rem` 이하 | 오더북 숨김, 차트와 주문 2열 |
| Mobile | `48rem` 이하 | 1열, 차트·오더북·주문 탭 전환 |

모바일 최소 지원 폭은 `32rem`입니다. 모바일에서는 상태 바와 데스크톱 내비게이션을 숨기고 거래 화면의 핵심 액션을 우선합니다.

## 공통 UI 컴포넌트

재사용 가능한 UI는 `src/components/ui`에 둡니다.

| 컴포넌트 | 역할 |
| --- | --- |
| `SelectMenu` | 제네릭 값 기반 선택 메뉴 |
| `Tooltip` | 인라인 또는 Portal 기반 안내 |
| `CheckboxField` | 주문 영역 체크박스와 선택적 도움말 |
| `UnitBadge` | 단위 또는 짧은 값 강조 |

기존 컴포넌트로 표현할 수 있는 UI를 기능 폴더 안에 중복 구현하지 않습니다. 여러 도메인에서 재사용하게 된 패턴은 `components/ui`로 승격합니다.

## 컴포넌트 상태 규칙

현재 SCSS는 BEM 형태의 클래스와 `is-*` 상태 클래스를 사용합니다.

- 블록: `.order`, `.book`, `.chart`
- 요소: `.order__field`, `.book__row`
- 변형: `.button--primary`
- 상태: `.is-active`, `.is-open`, `.is-negative`, `.is-loading`

상태 클래스는 시각 상태를 나타내고, 데이터나 테스트 식별자로 사용하지 않습니다. 버튼 선택 상태는 클래스뿐 아니라 `aria-pressed`, `aria-selected` 등 적절한 접근성 속성으로도 노출합니다.

## 아이콘과 이미지

- React에서 사용하는 아이콘은 `src/components/icons`의 SVG 컴포넌트로 관리합니다.
- 코인, 지원 상담원, 앱 스토어 이미지는 `src/assets/images`에 있습니다.
- 아이콘은 가능한 한 `currentColor`를 사용해 주변 텍스트 상태를 따르게 합니다.
- 의미 없는 장식 아이콘은 `aria-hidden="true"`로 처리합니다.
- 의미가 있는 아이콘 버튼에는 번역된 `aria-label`을 제공합니다.

루트의 `assets` 폴더에는 별도의 정적 스타일·폰트·이미지 자산도 존재합니다. React 앱에서 새로 사용하는 자산은 우선 `src/assets` 또는 React 아이콘 컴포넌트 체계에 맞춥니다.

## 다국어 UI

지원 언어는 한국어, 영어, 일본어, 중국어, 베트남어, 프랑스어입니다.

- 사용자에게 보이는 문구는 `useLocale().t()`를 사용합니다.
- 날짜와 숫자는 현재 언어에 맞는 로케일을 사용합니다.
- 긴 번역문을 고려해 고정 너비와 `nowrap` 사용을 최소화합니다.
- 언어 변경 시 `<html lang>`도 갱신됩니다.

현재 일부 한국어 원문이 깨져 보이는 구간이 있으므로 새 작업 전에 `src/i18n/Locale.tsx`와 각 컴포넌트의 인코딩을 점검해야 합니다.

## 접근성 기준

- 모든 아이콘 버튼에 목적을 설명하는 이름을 제공합니다.
- 키보드 포커스가 보이도록 유지합니다.
- 팝오버와 메뉴는 키보드로 열고 닫을 수 있어야 합니다.
- 폼 요소는 보이는 레이블 또는 접근 가능한 이름과 연결합니다.
- 색상 외에도 부호, 문구, 형태로 상태를 전달합니다.
- 실시간 값이 추가되면 화면 읽기 도구에 과도한 알림이 발생하지 않도록 갱신 영역을 설계합니다.
- 차트에는 요약 문구나 표 형태의 대체 정보를 제공합니다.

## UI 작업 체크리스트

- 기존 디자인 토큰과 공통 컴포넌트를 재사용했는가
- `padding`, `margin`, `gap`, 위치 간격 등 여백 값에 `src/styles/_tokens.scss`의 `$space-*` 토큰을 사용했는가
- 색상, 글자 크기, 모서리 반경, 애니메이션 시간도 각각 정의된 SCSS 토큰을 사용했는가
- 기존 토큰으로 표현할 수 없는 값은 임의로 반복하지 않고, 재사용 가능성과 의미를 확인한 뒤 토큰으로 추가했는가
- 클래스 이름은 현재 규칙인 BEM 형태와 `is-*` 상태 규칙을 따르는가
- 고정된 시각 스타일은 인라인 스타일이 아니라 SCSS에 작성했는가
- 새 z-index 값을 임의로 크게 지정하지 않고 기존 레이어 토큰 안에서 해결했는가
- Desktop, Tablet, Mobile 세 구간을 확인했는가
- `32rem` 최소 화면과 경계 구간인 `48rem`, `64rem`, `80rem` 전후에서 레이아웃이 깨지지 않는가
- 지원 언어 6개의 문자열 길이를 확인했는가
- 긴 가격, 수량, 퍼센트와 값이 없는 상태에서 줄바꿈·잘림·가로 넘침이 발생하지 않는가
- hover, focus, active, disabled, loading, empty, error 상태가 정의되었는가
- hover만으로 기능을 전달하지 않고 키보드 focus와 터치 환경에서도 사용할 수 있는가
- 버튼, 입력, 아이콘에 접근 가능한 이름과 명확한 포커스 표시가 있는가
- 상승·하락이 색상 외의 방법으로도 구분되는가
- 모션 감소 설정에서 기능을 이해할 수 있는가
- 새 이미지와 아이콘을 기존 `src/assets` 및 `components/icons` 구조에 맞게 배치했는가
- React 앱 스타일은 `src/styles`에서 수정하고 루트의 기존 `assets/css/style.css`를 직접 수정하지 않았는가
